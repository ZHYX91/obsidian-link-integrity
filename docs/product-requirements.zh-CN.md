# Link Integrity — 产品需求

本文定义 Link Integrity 的诊断结果、操作方式和数据边界。

## 产品定位

Link Integrity 是完全本地、默认只读的 Obsidian Vault 诊断插件。它提供两个主要视图：无效链接和孤立文件。插件帮助用户发现需要审查的链接关系，但默认不删除文件、不批量改写链接、不检查外部 URL，也不把“诊断结果”表达成自动清理许可。

## 有效 Vault 连接

有效连接是来源文件指向另一个当前存在 Vault 文件、且文件级目标已成功解析的显式内部引用。

- 自链接不连接两个文件，因此不计入有效入度或出度。
- 外部 URL 不属于 Vault 连接。
- 目标文件存在但标题或块缺失时，文件级连接仍然有效，同时产生标题或块无效诊断。
- 同一对文件之间的重复引用仍分别记录；连接统计也会保留不同引用类型各自的数量。

当前贡献显式连接的来源包括：

- Markdown 正文内部链接和嵌入；
- Frontmatter 中 Obsidian 识别的内部链接；
- Canvas 显式文件节点、背景文件以及可解析文本中的内部链接；
- Bases 的 `filters`、`formulas`、自定义 `summaries` 与视图 `filters` 中可静态识别的显式文件引用；视图名称、`properties` 展示配置以及普通字符串字面量不构成引用。

Bases 动态查询产生的结果不是显式引用，默认不算作文件连接。周期笔记只因日期相邻也不会被自动视为互相链接。

## 无效链接

无效链接按每一处引用分别报告，而不是只按目标汇总。当前确认的原因包括目标文件缺失、内部链接无效、标题缺失和块缺失。等待宿主元数据的链接不是已确认错误；无法验证的子路径也不会冒充已确认错误。

点击结果应打开来源，并在来源类型支持时定位到行、属性或 Canvas 节点。无法精确定位时，只打开来源文件并显示可用的 Canvas 节点 ID 或行列信息，同时明确不声称已经完成精确定位。

普通的结果隐藏规则只改变诊断可见性，不改变文件之间的有效连接，也不抹去孤立结果上的风险信号。

目标忽略按整个文件匹配，包含其标题和块引用；它不改变图贡献。单处忽略继续使用与位置无关的语义身份。规则预览分片运行，在索引替换后重新计数，较旧请求会被取消。

## 孤立文件

文件在有效图中同时满足以下条件时，才是默认意义上的孤立文件：

- 与其他现有 Vault 文件没有有效入链；
- 与其他现有 Vault 文件没有有效出链。

只有无效出链的文件仍然满足此定义，因为无效引用没有连接到现有文件。此类结果必须显示“孤立 · 含 N 处无效链接”一类的低置信度状态，不得作为高置信度清理项。

“无入链文件”是独立的高级查询。它可以包含仍有有效出链的文件，因此不能替代默认孤立定义，也不能自动解释为无用文件。

## 预期孤立

某些文件按工作流设计本来就可能孤立，例如周期笔记、模板或导出物。预期孤立规则只对已经满足孤立定义的候选文件分类：

- 默认从孤立主列表、主计数和高置信度清理候选中排除；
- 用户可通过高级选项显示，并查看匹配规则；
- 不创建日期邻接或其他推测连接；
- 不影响无效链接诊断，也不移除真实图贡献。

一条规则可以组合文件类型、文件夹和命名条件。不同条件之间是 AND；同一规则中的多个日期格式、glob 或正则命名模式之间是 OR。规则保存名称，并可计算匹配数量和少量样例。预览、保存和加载必须共享同一验证语义：超长、语法无效或超过安全子集的高级正则不能被静默删除后扩大规则范围，已有无效规则应整体停用并等待用户修正。内置周期笔记预设独立于 Chrono Notes 或其他插件运行，覆盖日、周、月、季和年格式，路径与命名格式均可配置。

用户也可以从单个孤立文件的行菜单将其“标记为预期孤立”。该操作只保存规范化后的精确 Vault 路径，不创建忽略规则、不改写文件，并提供即时撤销。孤立文件夹树的文件夹菜单可选择“仅此文件夹”或“包含子文件夹”；该操作创建一个没有额外文件类型或命名条件的文件夹规则，同样提供即时撤销。重命名事件会同步更新已保存的精确文件路径；已删除或暂时缺失的路径继续在设置中标明为缺失，直到用户移除。精确路径与规则匹配共享同一个预期孤立分类，但在设置中分别管理。

## 范围与文件类型

Link Integrity 严格分离三种范围：

- 候选范围：哪些文件可以出现在孤立文件结果中；
- 诊断范围：哪些无效链接结果在界面中可见；
- 贡献范围：哪些有效引用参与图计算。

未选择的候选类型和普通隐藏规则仍然贡献有效连接。只有单独的高级“排除图贡献”规则会改变图，而且界面必须警告它可能制造假孤立结果。

设置中的忽略规则以草稿编辑，修改控件不会立即改变诊断或连接统计。用户在当前就绪索引上预览后才能保存；规则内容、索引或已保存原规则发生变化时，旧预览不能授权提交。取消丢弃草稿。高级排除预览同时显示匹配引用数、涉及的不同文件数和有向文件连接数；同一来源到同一目标的重复引用只计一条连接，自链接不计。停用规则的预览展示启用后可能匹配的范围。

孤立候选使用统一的文件类型登记表：Obsidian 文件（Markdown、Bases、Canvas）、图片、音频、视频、版式文件（PDF）和其他附件。图片、音视频及附件按格式族细分，常见扩展名别名合并；匹配不区分大小写。未知附件只有在用户明确配置该自定义扩展名后才进入候选范围；选择“自定义”格式族但扩展名列表为空时，不能静默纳入所有未知文件。设置保存默认候选范围，侧栏筛选只是临时查询条件。

## 数据与安全边界

所有扫描、索引和规则匹配都在本地执行。插件只持久化设置、忽略规则和界面偏好，不持久化派生链接图。重启后重新建立当前 Vault 的权威索引。

插件的诊断模式是非破坏性的。自动删除、批量修复、外部 URL 网络检查以及把动态查询结果推断成显式连接，均不属于当前行为。

## 正文失效链接提示

正文提示是独立默认关闭的只读设置，仅标出已确认缺失的文件、标题或块引用。无效语法、pending、unsupported、索引未就绪或来源不可证明时不提示错误。显示沿用无效链接诊断开关与忽略可见性；标题/块缺失仍保留既有文件层面的有效图边。

只投影 LinkIndex 中真实显式 occurrence，不新增全 Vault 正文扫描，不改写笔记。当前已保存全文、源缓存、索引快照及正文语法须共同成立；属性、代码、注释、HTML 和数学等受保护范围不装饰。未保存正文或缓存等待期间允许暂时不显示。

阅读视图必须能证明唯一的来源引用与原生 anchor 对应。重复目的地、额外第三方 anchor、显示文字变换或虚拟替换等歧义均跳过；当前笔记诊断命令与侧栏保留只读查询和导航。FakeLink 虚拟文字不成为 occurrence、失效诊断或图边，不劫持原生点击、右键或第三方操作。

插件不提供潜在提及扫描、正文虚拟链接、手动候选选择、建立链接或专用撤销；旧提及设置安全忽略，既有真实链接不改写或还原。忽略规则与预期孤立标记的撤销继续保留。

# Link Integrity — 测试策略

Link Integrity 的测试策略优先证明诊断正确性和索引一致性，并严格区分自动门禁、打包候选、真实宿主和模拟器证据。

## 证据层级

不同证据回答不同问题，不能互相替代：

1. 静态和自动测试证明类型、纯语义、控制器和确定性契约；
2. 打包候选检查证明实际安装资产和版本契约；
3. 隔离真实 Obsidian Vault 证明宿主 API、导航和界面行为；
4. Android 模拟器证明受支持移动验收环境中的布局和宿主行为。

绿色构建不等于真实宿主验收。生产 Vault 不用于破坏性或首次验收实验。

按改动影响选择精确候选的代表性验收；桌面交互、设置或生命周期变化覆盖相关真实宿主场景，移动交互或影响移动端的共享运行行为变化覆盖相关 Android 模拟器场景。纯文档或无宿主影响的逻辑改动可记录理由后免宿主。影响本次发布的已确认严重产品缺陷应阻塞对应发布；宿主或工具缺项保留未验范围，按风险判断是否延后，不自动阻塞所有发布，也不增加一律再次确认的步骤。只有实际观察通过的范围可声称已验收。完整宿主矩阵不是每次发布的前提，CI 不自动检查宿主覆盖。分别记录桌面与模拟器实际覆盖范围。Android 真机和 iOS 不在共享验收范围内。

## 核心语义测试

纯测试 fixture 应覆盖：

- 文件存在、文件缺失、无效和等待解析状态；
- 标题和块成功、缺失、等待或无法验证状态；
- 文件存在但子路径缺失时仍保留文件级边；
- Markdown、嵌入、Frontmatter、Canvas 和 Bases 显式来源类型；
- 降级解析器屏蔽 fenced/indented code、HTML comment、原始 HTML code 和 frontmatter YAML comment，同时保留 frontmatter value 与 paragraph continuation 中的链接；回归覆盖 LF/CRLF/CR、空块、相邻块、两种围栏字符、不同长度、引用/列表嵌套、未闭合块及容器终止，以及 astral 字符前缀下的 UTF-16 offset；代码中的 HTML 字面、HTML 中的围栏、带引号的属性与类似标签的 Markdown 目标不能污染相邻正文；
- 自链接、外部 URL 和重复引用；
- Bases 动态结果不形成显式边；语义测试只允许 `filters`、`formulas`、自定义 `summaries` 与视图 `filters` 中的静态显式引用，并用视图名称、`properties` 展示字符串、公式内部普通字符串和 link 的动态第一参数作为负例；转义或折叠 YAML 不得伪造链接坐标或合并重复引用；
- 候选、诊断和贡献范围互不污染。

引用身份回归测试证明：在已保存引用前插入无关文本或无关链接后，其忽略匹配仍然保持；文件与文件夹重命名事件会迁移持久化身份中的来源部分。插入无法区分的同语义重复项时，重复集合基数必须变化，并让旧规则匹配零个结果，由规则预览明确呈现，而不是误匹配另一处引用。Workflow contract 的语法验证会把提取出的 shell 片段合并后交给单个 `bash -n` 进程，避免 Windows 门禁为每个代码块重复承担 Git Bash 启动开销。

文件类型登记表测试覆盖分类层级、扩展名别名、大小写、WebM 等重叠媒体分类、PDF 的版式文件归属和自定义扩展名。

## 孤立与规则测试

孤立结果测试必须证明默认定义同时要求有效入邻居和出邻居为零。只有无效出链的文件仍是孤立文件，并显示无效引用数量和需要谨慎判断的状态；自链接和外部 URL 不改变孤立状态。

无入链查询单独测试，确保有有效出链的文件不会进入默认孤立结果。候选类型筛选不能移除未选中文件贡献的真实连接。

预期孤立测试覆盖：

- 默认从主结果和主计数排除，高级显示时分类为 expected-isolated；
- 预期分类不创建任何图边；
- 文件类型、文件夹和命名条件使用 AND，多个命名模式使用 OR；
- exact/recursive 文件夹、日期格式、glob、安全子集 regex、匹配数和样例；regex 测试必须覆盖超长模式、重复次数或状态数超限、非法 flag、反向引用和 lookaround 的拒绝；差分测试用短输入对比支持子集与原生 Unicode 正则的语义，对抗基准覆盖嵌套或歧义分组和相邻重复，证明不执行原生回溯；
- 日、周、月、季、年周期笔记预设及可配置路径和格式；
- 无效规则不静默匹配所有文件；持久化的无效命名条件（包括显式非数组的 `namingPatterns` 或旧版 `patterns`）必须保留用于诊断并整体停用规则，不能因归一化或再次保存删除条件而扩大匹配；未提供命名条件和空数组仍是有效的无命名限制规则。
- 精确文件路径的规范化、去重、主计数排除、rename 跟随，以及缺失路径在设置中的可见移除。

## 全量与增量一致性

完整重建是增量实现的正确性基准。测试维护一个可变的虚拟 Vault，在每个 create、modify、delete 或 rename 后：

1. 让增量控制器处理事件并等待 idle；
2. 从当前虚拟 Vault 重新构建干净索引；
3. 比较文件、快照、引用状态、边计数和自链接的规范化状态。

Markdown 降级与 Canvas 文本的受保护范围回归必须经过真实 adapter、全量和增量控制器，验证有效与缺失目标从正文移入注释/代码再移回时，引用、无效链接、有效边和孤立结果同时更新，并与干净重建一致。

固定种子的随机事件序列用于重复验证差分等价。专项竞态测试覆盖同名文件出现后的有效与无效引用重验证、旧异步快照不能覆盖新 revision、重复事件合并、扫描前事件风暴由新的完整初始索引吸收且不重复建快照、扫描开始后的 create/modify/delete/rename 缓冲重放、Metadata Cache 超时后的 late `resolved` 单次全局纠偏和有限并发。图贡献规则测试使用同一规范化状态作为稳定差分指纹，证明 regraph 与新 policy 下的干净物化结果相同，同时不增加 adapter 读取或来源解析计数。

## 重建与故障测试

事务测试验证 staging 在完成前不可见，只有成功后才原子发布。构建失败时，store 保留相同的最近一次可信对象和 generation。

协调器测试覆盖重建期间事件缓冲与重放、同生命周期并发 rebuild single-flight、预重建增量失败后的生命周期恢复、stop 后旧重建不能发布或继续领取来源，以及 stop→start 后旧操作 finalizer 不能清理新控制器。时间片测试使用可注入 `yieldControl` 与可控时钟，分别验证文件数上限和主线程时间预算都会触发让步；进度测试验证节流和最终进度。

故障测试不应只断言抛错，还要断言可信索引是否保留、待处理事件能否继续处理，以及状态是否诚实标记为 failed 或 stale。首次完整建立失败且尚无可信索引时，还要用大批事件证明插件层不会线性保留历史队列；下一轮完整重建仍必须从当前 Vault 建立完整状态。同步 reducer 的定向 fault injection 会让同一批次的后一个来源制造跨来源引用 ID 冲突，并断言 batch 预验证在任何文件元数据或快照发布前失败。

## UI、设置与多语言测试

自动 UI 测试按以下操作分组：

- 导航与恢复：两业务页签、三设置页签、无常驻侧栏标题/刷新/设置行、首次建立索引、异常时重试，以及设置中的重建入口。
- 查询与布局：搜索、等宽视图切换、分组主按钮、目标/来源文件/来源文件夹原生选择、情境化排序、列表与树的排序约定、来源树计数和折叠分支惰性 DOM。
- 范围与分类：临时格式筛选、预期孤立高级显示、单文件及文件夹精确/递归标记、撤销和低置信度状态。
- 分页：固定 100 条结果，首尾页均可到达，徽标仍显示完整结果计数。
- 索引详情：默认折叠，计数来自 O(1) 诊断快照，关闭设置后解除订阅，失败只显示聚合信息；展开详情不读取 Vault 或导出整图。

忽略规则回归覆盖：修改与取消不提交；只有当前预览能启用保存；输入、索引发布、设置关闭取消请求；迟到结果不会恢复旧计数；已保存规则被其他动作修改时拒绝覆盖；空匹配值、停用草稿、新规则取消和未来 schema 写保护。DOM 核对作用范围、匹配方式、匹配内容的可访问名称；预览测试区分重复引用、不同文件连接与自链接。

规范检查 `npm run check` 必须执行覆盖率阈值；发布检查还必须实际执行快速与 5 万文件规模基准。大型来源文本基准覆盖显式链接位置换算与行内代码屏蔽，避免按链接数或反引号数退化为二次复杂度。

设置测试覆盖 schema 归一化、迁移、未来 schema 写保护、串行合并保存、失败待重试，以及所有受支持 Obsidian 版本共用的 imperative 顶部页签实现。规则编辑器测试还覆盖类型、匹配对象、模式与 flags 的可访问名称、验证消息关联以及无效草稿在预览前禁用保存；导航测试覆盖非 Markdown 来源无法精确定位时仍暴露节点或行列上下文。测试还必须证明 declarative definitions 保持为空，避免 Obsidian 绕过页签布局。键盘测试覆盖 tablist 角色、roving tabindex、方向键、Home/End、焦点保持和 RTL；DOM 测试不能代替真实 Obsidian 的样式和焦点验收。

宿主样式几何回归通过无额外依赖的真实 Chrome/Chromium 进程加载仓库中的实际 `styles.css` 和一份最小 Obsidian 宿主样式合同。它测量多行结果的行盒与溢出、长俄文徽标、宿主复选框的方形外观与至少 34px 的独立点击目标、原生 disclosure marker、对宿主按钮背景/阴影的覆盖、禁用 container query 时仍不溢出的 220px 侧栏回退、450px 自定义设置正文，以及 RTL 逻辑缩进。该测试属于自动浏览器证据并进入常规测试门禁；运行环境必须提供 Chrome/Chromium，或通过 `LINK_INTEGRITY_CHROME_PATH` 指定可执行文件。它不能替代真实主题、系统缩放、真实 RTL、粗指针设备或移动宿主验收。

导航 CSS 检查通过 CSSOM 核对选择器、各项声明和优先级。拆分规则或调整互不依赖的声明顺序不应使测试失败。浏览器几何与焦点测试仍负责验证宿主样式合同下的布局，声明检查不能替代它们。

i18n 门禁检查 12 个完整且独立的 catalog、编译期精确键覆盖、插值、复数、语言自称、“跟随 Obsidian”术语、稳定中英文文档结构和退役术语。README 检查使用读者对应界面的侧栏名称，并保留根文档 canonical 链接及译文相对链接的离线目标验证。帮助链接测试覆盖本地化指南目标和不写设置即可使用的行为。稳定 catalog 不允许通过展开英文对象补齐缺失翻译。

## 性能与规模

增量性能回归必须覆盖高入链笔记的普通正文修改：在 10k 和 50k 文件图中连续修改中心笔记 12 次，目标指纹保持已就绪且不变，断言只构建 12 个来源且不重新枚举 Vault 文件登记表；同时更新两类侧栏投影，保持旧索引与未变化结果数组不变。合成批次总耗时上限分别为 750 ms 和 1,500 ms，不代表真实宿主输入延迟。

调度与写时复制测试在每次让步观察已发布索引，证明完整批次发布前旧文件、快照、反向索引和边计数均不变化。覆盖两个分支各自修改、后续来源校验失败、让步期间新事件或停止、来源位置更新、标题/块/脚注指纹变化与未知元数据，以及全量并发读取的单一 reducer。查询测试比较分片与同步投影、增量与干净投影，并验证 inactive 页签累积变化、删除、忽略规则和无入链开关。UI 测试验证进度更新保留节点和焦点、复用行的点击参数正确、隐藏页签恢复、过期请求与关闭生命周期。

真实宿主响应性另用 Performance 记录检查插件长任务、输入延迟与内存峰值，分别对比禁用插件、索引已就绪但关闭结果标签页、打开结果标签页。CPU 降速模拟只能作为辅助，不能替代指定低配置机器；合成测试也不能证明单次宿主 API 或 JSON 解析满足调度预算。

合成基准分别记录文件数量、引用数量、来源类型分布、环境和耗时。快速门禁可以使用 10k 文件；50k 和必要时 100k 必须是明确运行的独立规模，不能因脚本参数失效而误报。

性能验收至少观察全量构建、单文件修改、命名空间 create/delete/rename、重复 Vault/Metadata Cache 回调突发、关闭启动扫描时的休眠状态、被忽略的启动期 `resolve(file)` 风暴、超时后 host-wide `resolved` 的一次性纠偏、仅图规则变更的零解析 regraph、相互独立的活动页签查询、规则预览和有界侧栏 DOM。阈值用于发现回归，不代表真实设备承诺；移动设备必须单独测量。

基准契约包含 10k 文件快速规模和显式 50k 文件规模；只有明确运行 100k 时才可报告该规模。图贡献基准为每个来源生成 3 个引用，并连续替换一个完整来源快照；它断言规则求值只与每批旧、新 occurrence 数量相关，且普通更新不会重建整图。10k 与 50k 的耗时上限分别为 500 ms 和 1,000 ms。heap delta 只作诊断输出，因为垃圾回收时序不适合作为稳定阈值。

活动页签基准必须证明刷新“无效链接”时不会计算非活动的孤立文件投影。孤立投影在 10k/50k 的上限为 2,000 ms/8,000 ms，“无效链接”的上限为 500 ms/1,000 ms。合成阈值用于发现回归，不能替代正式 Vault 的启动、交互掉帧或最长主线程任务测量。

## 打包与宿主验收

打包候选必须来自确定性生产构建，并验证实际运行资产只有 `main.js`、`manifest.json` 和 `styles.css`。隔离 Vault 安装应替换这三项并保留 `data.json`，再记录文件哈希和插件加载结果。

真实桌面宿主矩阵应至少覆盖 Obsidian 1.12.7 和当前 1.13.x，验证 Metadata Cache 边界、官方 resolver 结果、实时事件、精确导航、主题、窄侧栏、键盘和 RTL。移动验收另行覆盖触摸目标、后台/恢复、旋转、窄屏和较大 Vault 响应。

稳定仓库文档只记录可重复执行的矩阵和证据边界，不保存机器专有路径、run ID、截图、哈希或按日期累积的执行日志。发布判断必须另行保留精确候选与宿主记录，且不得把 smoke 检查升级描述为导航、实时事件或模拟器证据。

## 完成判定

一个候选只有在以下事实分别有证据时，才能作相应声明：自动门禁通过、候选资产契约通过、目标 Obsidian 版本在隔离 Vault 通过或模拟器通过。Android 真机和 iOS 不是本项目的验收层级。缺少某个受支持层级的证据不会否定其他层，但禁止把较低层证据升级描述为较高层验收。

发现失败时，应记录最小复现、受影响语义、最近一次可信状态以及修复后的回归测试。任何生产 Vault 部署都必须在独立验收完成后另行授权。

## 正文诊断回归与共存验收

缓存主路径与无缓存降级路径须对准确定位的 Obsidian 注释、代码及 YAML 注释引用保持一致，并覆盖 LF/CRLF/CR、嵌入、原生引用式链接、格式化标签及独立属性引用。实际适配器 10k/50k 来源基准检查每来源一次正文读取、屏蔽引用不进入图，以及 12 次单来源修改只有 12 次读取且不枚举注册表。真实 Chromium 样式回归同时加载宿主 unresolved 普通和 hover 选择器，确认自有提示保留警示色波浪线，未标记的原生及虚拟链接保持宿主样式；它仍不替代真实宿主验收。

自动回归覆盖默认 Off、缺字段与旧提及字段忽略、三个设置页、无旧命令/菜单、共享诊断开关/忽略、三类确认缺失与 pending/invalid/unsupported 负例、全文和 cache/snapshot 身份、等长前缀变代码/注释、CRLF/CR 坐标及保护语法。确认诊断不改变图与孤立结果，标题/块缺失仍贡献既有文件边。

阅读测试覆盖同 label 不同目标、同目的地重复原生引用、裸 #^block 与真实引用混排、第三方额外 anchor、embed/引用式链接/变换文字的保守回退、native href/点击保留、hover/focus/Escape、触摸诊断入口、OFF、异步关闭、DOM 变化与 surviving children 卸载。编辑器测试覆盖修改立即清除、IME、viewport 上限和取消。

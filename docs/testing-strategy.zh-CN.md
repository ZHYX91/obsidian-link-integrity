# Link Integrity 测试策略

Link Integrity 的测试策略优先证明诊断正确性和索引一致性，并严格区分自动门禁、打包候选、真实宿主、模拟器和物理设备证据。

## 证据层级

不同证据回答不同问题，不能互相替代：

1. 静态和自动测试证明类型、纯语义、控制器和确定性契约；
2. 打包候选检查证明实际安装资产和版本契约；
3. 隔离真实 Obsidian Vault 证明宿主 API、导航和界面行为；
4. Android 模拟器证明一个模拟移动环境中的布局和宿主行为；
5. 物理设备证明真实触摸、性能、文件系统和生命周期行为。

绿色构建不等于真实宿主验收，模拟器也不等于物理设备证据。生产 Vault 不用于破坏性或首次验收实验。

## 核心语义测试

纯测试 fixture 应覆盖：

- 文件存在、文件缺失、无效和等待解析状态；
- 标题和块成功、缺失、等待或无法验证状态；
- 文件存在但子路径缺失时仍保留文件级边；
- Markdown、嵌入、Frontmatter、Canvas 和 Bases 显式来源类型；
- 自链接、外部 URL 和重复 occurrence；
- Bases 动态结果不形成显式边；
- 候选、诊断和贡献范围互不污染。

文件类型 registry 测试覆盖分类层级、扩展名别名、大小写、WebM 等重叠媒体分类、PDF 的版式文件归属和自定义扩展名。

## 孤立与规则测试

孤立投影必须证明默认定义同时要求有效入邻居和出邻居为零。只有无效出链的文件仍是孤立文件，并具有无效 occurrence 数量和低置信度；自链接和外部 URL 不改变孤立状态。

无入链查询单独测试，确保有有效出链的文件不会进入默认孤立结果。候选类型筛选不能移除未选中文件贡献的真实连接。

预期孤立测试覆盖：

- 默认从主结果和主计数排除，高级显示时分类为 expected-isolated；
- 预期分类不创建任何图边；
- 文件类型、文件夹和命名条件使用 AND，多个命名模式使用 OR；
- exact/recursive 文件夹、日期格式、glob、regex、匹配数和样例；
- 日、周、月、季、年周期笔记预设及可配置路径和格式；
- 无效规则不静默匹配所有文件。

## 全量与增量一致性

完整重建是增量实现的 correctness oracle。测试维护一个可变的虚拟 Vault，在每个 create、modify、delete 或 rename 后：

1. 让增量控制器处理事件并等待 idle；
2. 从当前虚拟 Vault 重新构建干净索引；
3. 比较文件、快照、occurrence 状态、边计数和自链接的规范化状态。

固定种子的随机事件序列用于重复验证差分等价。专项竞态测试覆盖同名文件出现后的有效与无效引用重验证、旧异步快照不能覆盖新 revision、重复事件合并、启动 baseline 期间 create/modify/delete/rename 缓冲重放、全局 metadata-resolved 和有限并发。

## 重建与故障测试

事务测试验证 staging 在完成前不可见，只有成功后才原子发布。构建失败时，store 保留相同的 last-known-good 对象和 generation。

协调器测试覆盖重建期间事件缓冲与重放、并发 rebuild single-flight、预重建增量失败后的生命周期恢复，以及 stop 后旧重建不能发布。时间片测试使用可注入 `yieldControl`，进度测试使用可控时钟验证节流和最终进度。

故障测试不应只断言抛错，还要断言可信索引是否保留、待处理事件能否继续处理，以及状态是否诚实标记为 failed 或 stale。同步 reducer 的定向 fault injection 会让同一批次的后一个来源制造跨来源 occurrence ID 冲突，并断言 batch 预验证在任何文件元数据或快照发布前失败。

## UI、设置与多语言测试

自动 UI 测试应覆盖两业务页签、三设置页签、无固定侧栏标题/刷新/设置行、首次建立索引、异常时上下文重建、设置页常驻重建入口、搜索、排序、列表/树或分组视图、临时格式筛选、预期孤立高级显示、低置信度标记，以及固定 200 条分页的首尾页可达性。

设置测试覆盖 schema 归一化、迁移、未来 schema 写保护、串行合并保存、失败待重试，以及 1.12 imperative 与 1.13 declarative 定义共用同一数据来源。键盘测试覆盖 tablist 角色、roving tabindex、方向键、Home/End、焦点保持和 RTL；DOM 测试不能代替真实 Obsidian 的样式和焦点验收。

宿主样式几何回归通过无额外依赖的真实 Chrome/Chromium 进程加载仓库中的实际 `styles.css` 和一份最小 Obsidian 宿主样式合同。它测量多行结果的行盒与溢出、长俄文徽标、宿主复选框的方形外观与至少 34px 的独立点击目标、原生 disclosure marker、对宿主按钮背景/阴影的覆盖、禁用 container query 时仍不溢出的 220px 侧栏回退、450px declarative 自定义设置正文，以及 RTL 逻辑缩进。该测试属于自动浏览器证据并进入常规测试门禁；运行环境必须提供 Chrome/Chromium，或通过 `LINK_INTEGRITY_CHROME_PATH` 指定可执行文件。它不能替代真实主题、系统缩放、真实 RTL、粗指针设备或移动宿主验收。

i18n 门禁检查 11 个完整且独立的 catalog、编译期精确键覆盖、插值、复数、语言自称、“跟随 Obsidian”术语、稳定中英文文档结构和退役术语。稳定 catalog 不允许通过展开英文对象补齐缺失翻译。

## 性能与规模

合成基准分别记录文件数量、occurrence 数量、来源类型分布、环境和耗时。快速门禁可以使用 10k 文件；50k 和必要时 100k 必须是明确运行的独立规模，不能因脚本参数失效而误报。

性能验收至少观察全量构建、单文件修改、命名空间 create/delete/rename、重复 Vault/Metadata Cache 回调突发、被忽略的启动期 `resolve(file)` 风暴、孤立查询、规则预览和有界侧栏 DOM。阈值用于发现回归，不代表真实设备承诺；移动设备必须单独测量。

当前实现已经运行本地合成 10k 和显式 50k 模式。2026-08-02 的本轮候选在精确 runtime 上以 116.9 ms 完成 10k 建图与孤立投影；显式 50k 模式为 606.0 ms，包含 guardrail 的完整 50k 基准测试为 955 ms。100k 尚未验证，不能从 50k 结果推断。

2026-08-06 的专项 graph-ignore 基准为每个来源生成 3 个 occurrence，并对同一个来源连续替换完整快照。10k/29,700 occurrence、12 个批次下，旧的全量扫描对照执行 356,400 次规则求值和 12 次整图重建、耗时 659.6 ms；局部 policy 路径只执行 72 次求值、0 次整图重建、耗时 0.4 ms。显式 50k/149,700 occurrence、6 个批次下，对照为 898,200 次求值、6 次整图重建和 1,746.6 ms，局部路径为 36 次求值、0 次整图重建和 0.3 ms。门禁精确断言求值次数等于每批旧、新 occurrence 数且普通更新不重建整图，并分别使用 500 ms/1,000 ms 的宽松耗时上限；同次进程观测到的 heap delta 会输出但不作阈值承诺，因为它受垃圾回收时序影响。

## 打包与宿主验收

打包候选必须来自确定性生产构建，并验证实际运行资产只有 `main.js`、`manifest.json` 和 `styles.css`。隔离 Vault 安装应替换这三项并保留 `data.json`，再记录文件哈希和插件加载结果。

真实桌面宿主矩阵应至少覆盖 Obsidian 1.12.7 和当前 1.13.x，验证 Metadata Cache 边界、官方 resolver 结果、实时事件、精确导航、主题、窄侧栏、键盘和 RTL。移动验收另行覆盖触摸目标、后台/恢复、旋转、窄屏和较大 Vault 响应。

## 完成判定

一个候选只有在以下事实分别有证据时，才能作相应声明：自动门禁通过、候选资产契约通过、目标 Obsidian 版本在隔离 Vault 通过、模拟器通过、物理设备通过。缺少某层证据不会否定其他层，但禁止把较低层证据升级描述为较高层验收。

发现失败时，应记录最小复现、受影响语义、last-known-good 状态以及修复后的回归测试。任何生产 Vault 部署都必须在独立验收完成后另行授权。

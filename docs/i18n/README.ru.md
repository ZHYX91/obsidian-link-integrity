# Link Integrity

[English](../../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [Tiếng Việt](README.vi.md) · [العربية](README.ar.md)

Link Integrity помогает находить неработающие ссылки и файлы, не связанные с другими существующими файлами в хранилище Obsidian. Плагин показывает результаты проверки, но не меняет ссылки и не удаляет файлы.

## Возможности

- По желанию отмечает подтверждённое отсутствие файлов, заголовков и блоков волнистой линией предупреждающего цвета.
- Находит внутренние ссылки на отсутствующие файлы, заголовки и блоки в Markdown, встраиваниях, Frontmatter, Canvas и явно указанных файловых ссылках Bases.
- Находит файлы без допустимых входящих и исходящих связей с другим существующим файлом Vault. Ссылки на себя и внешние URL не считаются связями внутри Vault.
- Отдельно предупреждает, если в изолированном файле есть неработающие исходящие ссылки, чтобы такой файл не выглядел очевидным кандидатом на удаление.
- Периодические заметки, шаблоны, архивы и похожие файлы можно пометить как Ожидаемо изолирован. Это меняет только их категорию в результатах и не меняет реальные ссылки.
- Фильтрует изолированные файлы по типам Obsidian, форматам изображений, аудио, видео, PDF и настроенным расширениям вложений.
- При необходимости строит полный индекс и затем автоматически обновляет его при изменениях Vault.
- Открывает источник каждой найденной проблемы, когда точная навигация доступна. Проверка и индексирование выполняются локально.

Динамические результаты запросов Bases не считаются ссылками автоматически. Если целевой файл существует, но в нём нет нужного заголовка или блока, файлы всё равно считаются связанными, а отсутствующий заголовок или блок показывается отдельной ошибкой.

## Требования и совместимость

- Obsidian 1.12.7 или новее.
- Поддерживает настольную и мобильную версии Obsidian. Формальная проверка разделяет настольный хост и эмулятор Android; реальные устройства Android и iOS не входят в её область.
- Проверяется только текущий Vault. Внешние сайты и удалённые ресурсы не проверяются.

## Установка

Откройте **Настройки → Сторонние плагины → Обзор**, найдите **Link Integrity** и установите его. Если плагин ещё не отображается в каталоге, скачайте `link-integrity-<version>.zip` из [последнего выпуска GitHub](https://github.com/ZHYX91/obsidian-link-integrity/releases/latest).

Для ручной установки поместите `main.js`, `manifest.json` и `styles.css` в `Vault/.obsidian/plugins/link-integrity/`. Затем перезагрузите Obsidian и включите Link Integrity. При обновлении заменяйте только эти три файла и сохраняйте `data.json`, если не хотите сбросить настройки.

## Использование

1. Включите Link Integrity в сторонних плагинах.
2. Откройте Link Integrity с ленты или из палитры команд. В боковой панели есть **Неработающие ссылки** и **Изолированные файлы**.
3. Выберите результат, чтобы открыть его источник. Фильтры изолированных файлов меняют только текущий вид и не затрагивают сохранённые настройки по умолчанию.
4. Сканирование при запуске по умолчанию отключено. При открытии боковой панели индекс создаётся по необходимости; также можно использовать **Построить индекс** или **Перестроить индекс** в общих настройках. После первого успешного построения изменения Vault автоматически обновляют результаты.

Включите **Показывать неработающие ссылки в тексте** в разделе **Неработающие ссылки**, чтобы видеть подсказки при чтении и редактировании. По умолчанию функция отключена и не меняет способ открытия ссылок. Команда **Проверить ссылки в текущей заметке** в палитре команд показывает причины и позволяет перейти к источнику. Обновляющиеся ссылки и ссылки без точно определённой позиции остаются без отметки; проверяйте их в боковой панели.

## Настройки

Пункты **Руководство пользователя** и **Сообщить о проблеме** находятся в разделе **Общие → Справка и поддержка**. Руководство открывается на языке интерфейса.

Например, если `A.md` ссылается на существующий `[[B]]`, он не изолирован даже при отсутствии входящих ссылок. Если внутри есть только `[[Missing]]` и нет других действительных связей, файл остаётся изолированным, но его следует проверить, а не сразу удалять.

- **Общие**: язык, сканирование при запуске, представления по умолчанию и команды построения/перестроения индекса. Язык по умолчанию — **Следовать Obsidian**.
- **Неработающие ссылки**: какие ошибки показывать и какие именованные правила исключения использовать, с предварительным просмотром совпадений.
- **Изолированные файлы**: типы файлов по умолчанию, необязательный режим без входящих ссылок, Ожидаемо изолирован, правила исключения и правила ожидаемой изоляции.
- Правила ожидаемой изоляции могут сочетать тип файла, одну папку или папку с подпапками, форматы даты, glob-шаблоны и расширенные регулярные выражения. Предустановка периодических заметок поддерживает день, неделю, месяц, квартал и год.

**Важно о расширенных правилах игнорирования:** «Ожидаемая изоляция» и обычное скрытие результатов не меняют связи. Расширенная настройка исключения подходящих ссылок из анализа связей перестаёт учитывать их при подсчёте, из-за чего даже реально связанные файлы могут выглядеть изолированными. Сначала проверьте совпадения.

Настройки и пользовательские правила хранятся в `data.json`. Рассчитанный индекс ссылок хранится только в памяти и после перезапуска создаётся заново.

Разверните правило исключения или выберите **Добавить правило игнорирования**. Задайте **Область действия**, **Способ сопоставления** и **Значение для поиска**, затем нажмите **Предпросмотр**. Проверьте совпадения, примеры и количество затронутых файлов и связей перед нажатием **Сохранить**. До сохранения изменения остаются в черновике; **Отмена** их отменяет. После изменения правила или индекса нужен новый просмотр. Если актуального индекса нет, сначала создайте его в разделе **Общие**. Отключённое правило тоже можно просмотреть: результат покажет область действия после включения.

## Ограничения

- Link Integrity не удаляет файлы и не переписывает ссылки. Неопределённый текст не отмечается; другие ошибки доступны на боковой панели.
- Внешние URL намеренно не проверяются и не запрашиваются по сети.
- Динамические результаты Bases не считаются прямыми связями между файлами; учитываются только явно указанные ссылки.
- Правила ожидаемой изоляции меняют только категорию уже изолированных файлов. Они не скрывают неработающие ссылки и не удаляют реальные связи.

## Конфиденциальность и безопасность

Индексирование выполняется локально. Плагин не загружает Vault, не требует учётной записи и не меняет текст. Производный индекс хранится в памяти.

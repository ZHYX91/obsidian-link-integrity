Link Integrity — локальный диагностический плагин Obsidian только для чтения, предназначенный для Broken links и Isolated files.

## Снимки экрана

Проверяйте битые ссылки и изолированные файлы в компактной боковой панели:

Настраивайте индекс, правила исключения, типы файлов и ожидаемую изоляцию в параметрах Obsidian:

![Настройки Link Integrity](../assets/link-integrity-settings-en.png)

## Возможности

- Находит битые внутренние ссылки на файлы, заголовки и блоки в Markdown, встраиваниях, Frontmatter, Canvas и явных файловых ссылках Bases.
- Выявляет файлы без допустимых входящих и исходящих связей с другим существующим файлом Vault; ссылки на себя и внешние URL связей не создают.
- Помечает изолированные файлы с битыми исходящими ссылками как менее надёжные.
- Отдельно показывает периодические заметки, шаблоны и архивы как Expected isolated, не создавая искусственных рёбер графа.
- Фильтрует файлы Obsidian, форматы изображений, аудио, видео, PDF и настроенные расширения вложений.
- При необходимости строит полную базу, после чего обновляет её инкрементально.
- Открывает источник каждой диагностики; анализ и индексирование выполняются локально.

Динамические результаты Bases не считаются явными рёбрами. Если файл найден, но заголовок или блок отсутствует, связь на уровне файла сохраняется, а ошибка подпути сообщается отдельно.

## Требования и совместимость

- Obsidian 1.12.7 или новее.
- Предназначен для настольных и мобильных устройств; каждый реальный хост и устройство остаётся отдельной границей приёмки.
- Диагностируется только текущий Vault, внешние сайты не проверяются.

## Установка

Первая публичная версия ожидает финальной приёмки. После публикации установите Link Integrity через **Настройки → Сторонние плагины → Обзор** или скачайте `link-integrity-<version>.zip` из [последнего выпуска](https://github.com/ZHYX91/obsidian-link-integrity/releases/latest).

Для ручной установки поместите `main.js`, `manifest.json` и `styles.css` в `Vault/.obsidian/plugins/link-integrity/`. При обновлении заменяйте только эти три файла и сохраняйте `data.json`, если не требуется сброс настроек.

## Использование

1. Включите Link Integrity в сторонних плагинах.
2. Откройте боковую панель с ленты или из палитры команд и переключайтесь между **Broken links** и **Isolated files**.
3. Выберите диагностику, чтобы открыть источник; фильтры меняют только текущий вид.
4. Если сканирование при запуске отключено или база не построилась, используйте **Построить индекс** или **Перестроить индекс** в общих настройках. Затем результаты поддерживаются инкрементально.

## Настройки

- **Общие**: язык, сканирование при запуске, группировка и действия с индексом. По умолчанию — **Следовать Obsidian**.
- **Broken links**: категории диагностики и именованные правила исключения с предпросмотром.
- **Isolated files**: типы файлов, необязательный анализ без входящих ссылок, видимость Expected isolated и правила.
- Правила ожидаемой изоляции могут объединять тип, точную или рекурсивную папку, формат даты, glob и регулярное выражение; шаблон периодических заметок охватывает день, неделю, месяц, квартал и год.

Настройки и правила хранятся в `data.json`; производный граф не сохраняется.

## Ограничения

- Плагин не удаляет файлы и не переписывает ссылки автоматически.
- Внешние URL не запрашиваются по сети.
- Динамические запросы Bases не считаются явными связями.
- Правила Expected isolated влияют только на представление кандидатов и не скрывают битые ссылки.
- Автоматические тесты не заменяют приёмку в реальных версиях Obsidian и на устройствах.

## Конфиденциальность и безопасность

Всё выполняется локально. Link Integrity не загружает содержимое Vault, не требует учётной записи, не изменяет заметки и не сохраняет производный граф.
